# M4c 集成设计：自研决策接入掼蛋托管（2026-09-10）

目标：把 MVP 的"点提示钮（借游戏 AI）"替换为**我们自己的决策**（`guandan/rules.py` + `guandan/ai.py`），
使用与斗地主同一套方法论：**视觉感知 → 规则/决策 → 坐标点击 → 回执校验**。

## 1. 感知（Perception）
| 需要什么 | 怎么拿 | 预算 |
|---|---|---|
| 是否轮到我 | 底部手牌带白卡像素 > 阈值（源码：仅轮到我时画手牌） | 0（像素） |
| 我的手牌（27/变少） | 手牌带 y[805,945]，**切两半** VLM 读 → 拼接去重 → 消毒（同点≤8、王各≤2、总≤27） | 1-2 次 VLM/回合 |
| 上家/各家最近出牌 | 出牌区四方位（源码坐标见《M4_掼蛋几何参考》§3），内容感知白卡 bbox → 裁剪 → VLM 读 | 1 次 VLM（仅当有新出牌） |
| 是否"不出" | 出牌区对应位置出现文字"不出"（源码 drawPassText）→ 可用小面积文字检测/VLM 兜底 | 可选 |
| 级牌 | 顶部/玩家信息条显示"打X"（drawPlayerInfo 画级牌）→ 小裁剪 VLM 或像素 | 每局 1 次 |
| 结算/续局 | 大金钮（开始/再接一局）色块 | 0（像素） |

## 2. 决策（Decision）
- Python 侧：`guandan.rules.identify/can_beat/find_all_plays` + `guandan.ai.choose_play(hand, last_play, state)`
- 角色/队友信息：`teamLogic` 移植（我=南、队友=北；东/西为对手）
- 决策回执校验：候选必须通过 `can_beat`，否则视为不合法（防 VLM 误读手牌导致的非法出牌）

## 3. 执行（Action）
- 手牌点选坐标（实测）：`x_i = 2 + i*24 + 20`，`y = 875`（i=0..n-1，按**当前手牌升序**排布）
  - 再点同一张 = 取消（toggle）；选中牌上移 36px（设备像素）
- 出牌 (359,1119) / 不出 (519,1119) / 提示 (199,1119)
- 校验回执：出牌后 1.5-2s 检查(a)手牌白卡像素下降 或 (b)本轮出牌区出现我方牌 → 成功；
  失败 → 重试一次 → 仍失败则回落到"提示钮执行"（安全网，与斗地主一致）

## 4. 与 MVP 的关系（渐进替换）
M4b（已完成）：轮次判定 + 提示钮 + 不出 + 结算续局 ← 现在能连续打
M4c-1：接入 rules/ai 做**跟牌决策**（上家牌型可读到时），失败回落提示钮
M4c-2：接入**领出决策**（首发/大牌权）
M4c-3：队友配合策略调优（不压队友、让牌）
M4d：长测 + 统计（局数/头游率/升级进度），对齐斗地主的统计与夜跑机制

## 5. 风险
- 手牌 VLM 读数偶发（服务端排队）→ 沿用"消毒+重试3次"；决策侧可用像素数牌做一致性校验
- 主牌（红桃级牌）万能牌型组合复杂 → 先按"不主动用作万能，仅按原值"降级策略，二期再加
- 出牌区文字（"不出"）识别 → 先用简单模板/像素，必要时 VLM
