# 云手机自动化挂机斗地主 可行性研究报告

**版本**: V1.0
**日期**: 2026-08-24
**性质**: 技术 + 商业双维度可行性论证

---

## 一、项目概述

利用**云手机**（云端安卓虚拟机）+ **AI智能体**（视觉识别 + 强化学习决策 + RPA操作），实现欢乐斗地主等棋牌游戏的**自动化挂机**，并以服务/工具形式对外交付。

**核心问题**：技术上是否可行？商业上是否赚钱？风险是否可控？

---

## 二、技术可行性（调研结论：✅ 高度可行）

### 2.1 已有成熟技术底座

| 技术层 | 成熟方案 | 出处/来源 | 成熟度 |
|--------|---------|----------|--------|
| **斗地主 AI 决策** | DouZero（快手 AI 平台，ICML 2021）— 深度强化学习自博弈，击败此前所有开源斗地主 AI，超越多数人类玩家 | arXiv:2106.06135, github.com/kwai/DouZero | ★★★★★ 开源可用 |
| **全自动挂机** | DouZero_For_HLDDZ_FullAuto — 基于 DouZero 的欢乐斗地主全自动版：自动截屏识别、自动出牌、自动叫牌、自动加倍、自动续局 | github.com/Vincentzyx/DouZero_For_HLDDZ_FullAuto | ★★★★ 社区验证 |
| **屏幕识别** | 视觉截屏识别（模板匹配/OCR）+ 屏幕区域截屏，项目已实现"窗口遮挡不影响游戏" | 同上项目 | ★★★★ |
| **云手机底座** | 安卓云手机虚拟化（Kata Containers / 云真机 / ARM 云服务器），单实例成本已降至 数十元/月 量级 | 行业公开报价（红手指等云手机厂商） | ★★★★★ 商业化成熟 |
| **RPA 操作层** | ADB 控制、模拟点击、UI 自动化（本项目已实现 ADB 截屏 + 操作骨架） | 本项目 landlord-counter | ★★★★ |

### 2.2 关键判断
- **决策层**：DouZero 开源模型可直接加载（`baselines/*.ckpt`），无需从零训练——**技术门槛被大幅降低**。
- **感知层**：截屏识别已有完整实现，含自动叫牌/加倍原理（自博弈胜率预测 + 阈值决策）。
- **运行层**：云手机本质是标准安卓环境，ADB/自动化工具全兼容。
- **结论**：所有技术组件均有**可验证的开源实现**，本项目的创新点在于**整合 + 产品化**，而非从零研发。

## 三、商业可行性（调研结论：⚠️ 需求真实，但需谨慎定位）

### 3.1 市场需求（闲鱼售价参考）
> 数据来源：用户提供的闲鱼商品截图（2026-08）

**欢乐豆交易市场（已有真实交易）**：
| 商品 | 售价 | 模式 |
|------|------|------|
| 100万欢乐豆 | ¥2.88 | 自动发货兑换码 |
| 500万欢乐豆 | ¥30 | 手动私聊 |
| 1200万欢乐豆 | ¥45 | 手动私聊 |
| 1500万欢乐豆 | ¥50 | 手动私聊 |
| 3000万欢乐豆 | ¥90 | 手动私聊 |
| 1亿欢乐豆 | ¥234 | 手动私聊 |

**推论**：
- 欢乐豆是硬通货，玩家为"赢豆"付费意愿真实存在；
- 挂机产豆 = 持续稳定产出欢乐豆 → 可对接该变现渠道；
- 但欢乐豆交易本身有平台风险（腾讯打击第三方交易），需谨慎。

### 3.2 商业模式选项

| 模式 | 客单价 | 风险 | 可行性 |
|------|--------|------|--------|
| A. 挂机服务（帮客户托管账号赢豆） | ¥30-100/月 | 高（账号风险/平台封禁） | ⚠️ 中 |
| B. 软件工具（卖挂机软件+教程，自用） | ¥99-299/次 | 中（被平台打击） | ⚠️ 中 |
| C. 技术方案交付（卖给工作室/云手机厂商） | ¥5,000-50,000/单 | 低（B端合规） | ✅ 推荐 |
| D. 开源+捐赠/增值服务 | 免费+¥增值 | 低 | ✅ 稳妥 |

### 3.3 成本测算（挂机服务模式）
| 成本项 | 月成本 |
|--------|--------|
| 云手机实例（低配，24h挂机） | ¥20-50/台 |
| 每台可挂账号数 | 1-2个 |
| 单账号月毛利（按¥30-50收费） | 约 ¥10-50（扣除平台抽成/封号损耗） |

**结论**：C端挂机服务毛利薄且风险高；**B端技术交付利润率高、风险可控**。

## 四、技术路径（分四阶段）

```
Phase 1: 单机验证（1-2周）
  本地模拟器/真机 + 现成 DouZero 模型 + 截屏识别
  → 验证：能自动打完一整局
  └ 本项目已完成的: ADB截屏/模板识别/记牌逻辑/规则引擎(斗地主+掼蛋)

Phase 2: 全自动闭环（2-4周）
  自动叫牌/加倍/出牌/续局 + 异常处理（断线重连/弹窗/验证码）
  → 验证：无人值守连续打 100 局，统计胜率与豆子盈亏

Phase 3: 云手机适配（2周）
  部署到云手机（红手指/多多云/自建ARM集群）
  → 验证：云端 7x24 稳定运行，资源占用可控

Phase 4: 产品化（2-4周）
  B端交付：管理面板（多实例监控）、API、批量部署脚本
  → 交付物：EXE / Docker 镜像 / MCP 组件
```

## 五、要攻克的难点（按难度排序）

| 难点 | 说明 | 解法方向 |
|------|------|---------|
| 1. **平台风控/封号** | 腾讯对自动化检测严格，异常操作模式会触发封禁 | 随机化操作间隔、模拟人类点击轨迹、单IP单账号 |
| 2. **识别鲁棒性** | 游戏更新/分辨率变化/弹窗打断 | 多模板+动态校准+VLM兜底（本项目已设计双链路） |
| 3. **长稳运行** | 7x24 挂机内存泄漏/断线/掉帧 | 看门狗 + 定期重启 + 状态机异常恢复 |
| 4. **胜率优化** | DouZero 基础模型在真实对局中胜率约50-55%，需针对欢乐斗地主调优 | 自博弈微调、对手行为建模（大模型分析层） |
| 5. **合规风险** | 第三方交易欢乐豆违反腾讯用户协议 | 定位B端技术交付，规避C端代打 |

## 六、风险与合规（必须正视）

1. **平台协议风险**：自动化挂机违反腾讯《用户协议》，封号不可避免（账号损耗计入成本）。
2. **法律风险**：倒卖虚拟货币/代练服务在灰色地带，B端交付更安全。
3. **道德风险**：自动化赢豆影响游戏公平性，建议仅用于测试/自用/技术演示。
4. **免责声明**：本项目（landlord-counter）定位为**技术学习与研究**，请勿用于商业作弊。

## 七、结论与建议

| 维度 | 结论 |
|------|------|
| 技术可行性 | ✅ 高 — 所有组件均有开源验证（DouZero 全家桶） |
| 商业可行性 | ⚠️ 中 — C端薄利高风险，B端技术交付是正解 |
| 推荐路径 | **先做 Phase 1-2 验证真实胜率与稳定性 → 再决定 B/C 端方向** |
| 时间预估 | 技术验证 1-2 个月，产品化 1-2 个月 |

**一句话**：技术不是瓶颈（已有开源全自动方案），**商业定位与风控才是成败关键**。建议先花两周跑通"全自动打100局"验证真实豆子盈亏，用数据决定是否继续投入。
