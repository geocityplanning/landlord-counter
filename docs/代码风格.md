# 代码风格约定

> 用户 2026-09-17 要求：「清理一下现有的代码，精简一下代码，之后的代码写作风格也尽量优雅简洁」✓
> 这份文档是**硬约定** —— 新写的代码一律照它来 ✓

## 一、注释

- **注释说"为什么"**，不说"是什么" —— 代码本身已经说了是什么 ✓
- **踩过的坑必须留痕**：一句话写清"错在哪、为什么这么改"，并带上日期 ✓
  ```python
  # ✗ 别这样:  # 遍历所有牌位
  # ✓ 这样:     # 顶边法会被抬起牌右上角露出的白条污染(2026-09-17) → 改用模板滑动 ✓
  ```
- 中文注释，一句话说完；标点用 `✓` 表示"已确认"，`✗` 表示"已验证错误" ✓

## 二、函数

- **一个函数只做一件事**；超 60 行就该拆 ✓
- **早退代替嵌套** —— 守卫条件写在最上面，主体别缩进三层以上 ✓
- **名字即文档**：`mask_you_label` / `slide_best` / `hand_band_measured` ✓ 不用 `do_stuff` / `helper2` ✗

## 三、数值

- **所有实测出来的数值必须集中成常量**，并注明**来源** ✓
  ```python
  CARD_W = 24          # 牌距, 实测(2026-09-17)
  LIFT_PX = 36         # 抬起量, 实测: 平放顶边 815 / 抬起 779
  MAX_DIST = 0.6       # 模板匹配距离上限
  ```
- **禁止在业务代码里出现硬编码坐标** —— 一律走 `hand_band_measured()` / 自适应 ✓
  （产品硬约束：闭源游戏，坐标必须**实测锚点驱动** ✓）

## 四、工具脚本

- **一次性排查脚本不进仓库** ✗ —— 用 `/tmp` 或写完即删 ✓
- `tools/` 里**只留日常要用的**（验收/采集/运行/诊断 四类）✓
- 工具名 `动词_对象.py`：`tm_verify.py` / `what_raised.py` / `mark_raised.py` ✓

## 五、改动纪律

1. **改完必跑** `tools/tm_verify.py` —— 掉读数就回滚 ✓
2. **一次只改一件事**，改完立刻 commit（消息写清"为什么"）✓
3. **淘汰的实现在删之前先查真实调用点**（`grep -rn '\bname\s*('`）✓
   —— 反复出现过的教训：删/改前先 grep，别靠记忆 ✓
