# 承载稳定性工程记录：白屏 / 不吃点击的根因与处置（2026-09-14）

## 一、现象

掼蛋托管在 Firefox Focus 上跑一段时间后，会频繁进入两类异常：

1. **白屏**：页面整片变白（手牌带白卡像素从正常 ~66k 飙到 10 万+），截屏仍是 720×1280 但内容为空白。
2. **不吃点击**：页面看着正常，但点击（提示/出牌/不出）无任何反应，托管原地打转。

观测到的直接后果：单窗（55 分钟）产出从 20+ 局掉到 0-2 局；日志里出现大量"动作无效"与空转。

## 二、排查与证据

| # | 检查项 | 结果 | 结论 |
|---|---|---|---|
| 1 | Focus 进程列表 | 出现 `org.mozilla.focus:tab39`（标签页进程序号堆到 39+） | 页面进程反复重建，序号累计 |
| 2 | logcat 过滤 focus/gecko/crash | `GeckoChildProcessServices ... crashed` **88 次/日志窗口**，间隔约 **3-4 分钟** | Gecko **GPU（合成器）子进程周期性崩溃** |
| 3 | 内容进程 | 同一窗口出现 **26 个不同的 `:tabN` 进程号** | 渲染进程也在反复重建 |
| 4 | 图形栈 | `gfx-shader-check.device-id = "Google SwiftShader"` | 容器无真实 GPU，全靠软件光栅化（崩溃高发环境） |
| 5 | 主机内存 | total 7270MB，**available 5.1GB** | **不是内存不足**（排除 OOM 直觉） |
| 6 | tombstone | 只有系统 WebView 的 SIGTRAP（WebView Shell 测试时） | Gecko/Bromite 的死亡**不是原生崩溃**，而是进程被清 |
| 7 | **空闲对照实验**（关键） | 同一浏览器载着页面、**不驱动**，10 分钟采样 **30/30 全部存活**；且 `app died, no saved state` 的时间点与日志里的 `[看门狗] 重开浏览器` 次数/时间**吻合** | **"浏览器死了"里有一大部分是我们自己的自愈 force-stop 干的** |

## 三、结论（两个独立原因，叠加放大）

1. **环境侧**：redroid 容器（软件渲染 SwiftShader）里，Gecko 的 GPU/合成器子进程会周期性崩溃（3-4 分钟一次）→ 页面变白、输入送给已死进程 → "白屏/不吃点击"。
2. **我们代码侧**：健康检查（单帧白屏判据）会被**发牌/换屏动画帧**误触发 → 触发重开页面 → force-stop 浏览器 → **自杀式打断当局**，把偶发问题放大成常态低产。

## 四、处置

### 4.1 换承载：Firefox Focus(Gecko) → Bromite 108 x64（Chromium 自带引擎）

- 选型排除：
  - **自建 WebView APK 路线不可行**：本镜像系统 WebView 已损坏——`org.chromium.webview_shell` 启动即 **SIGTRAP**（tombstone 实锤），logcat 见 `NoClassDefFoundError: Landroid/webkit/PacProcessor`；系统 WebView 只能取主资源、子资源失败。
  - **Cromite（uazo/cromite）最新版要求 API 29+**，本设备 Android 9（API 28）直接 `INSTALL_FAILED_OLDER_SDK`。
- 落地：`x64_ChromePublic.apk`（Bromite 108，minSdk 23，172MB）经 gh-proxy 下载 → 安装（大包会让 adbd 掉线，`docker restart cloudphone-redroid` 后确认已装上）。
- 启动用**显式组件**避开系统选择器：
  `am start -a android.intent.action.VIEW -d <url> -n org.bromite.bromite/com.google.android.apps.chrome.Main`
- 配置化：`BROWSER_PKG`（默认 `org.bromite.bromite`）/ `BROWSER_ACT`（默认 `com.google.android.apps.chrome.Main`）；`tools/guandan_prep.py`、`agent._recover_page()`、`platform/device.py` 三处统一读它。

**效果**：Gecko GPU 崩溃计数 **88 → 0**（同一日志窗口口径）。

### 4.2 健康检查误报治理

- 白屏判据放宽：手牌白卡阈值 80k → **110k**（27 张正常 ≈66k）；中部"整片白"要求 **RGB>200**（纯白）才算。
- 触发条件收紧：**连续 2 帧异常 **且** 60 秒无任何进展**才重开（原来是单帧 + 25s）。
- 留 `GUANDAN_NO_HEALTH=1` 开关做 A/B 对照。

**效果**：误判重开 **8 次/12 分钟 → 0 次**。

### 4.3 换承载后的重新标定：选中"抬起量"基线

- 现象：Bromite 下**未选牌时** `lifted_px` 基线就有 **~3342**（Focus 下≈0，因其页面视口/工具栏不同）。
- 后果：旧代码用**绝对抬起量**估算提示选中张数（`round(lift/1460)`）→ 凭空多算 2-3 张 → 与决策给出的张数不符 → 不停 `mismatch` 回落，出牌链路看似失效。
- 修正：取**点选前那一帧**做基线，`est = round((lift_after - lift_before)/1460)`，阈值一律用增量（>500）。

**效果**：单窗 `mismatch` / `出牌未生效` / `点选不中` **全部归 0**。

## 五、验证数据（同口径 12 分钟窗口）

| 指标 | 处置前（Focus） | 处置后（Bromite） |
|---|---|---|
| 完成局数 | 0-2 | **5** |
| 出牌动作生效 | 少且反复回落 | **43 次** |
| 误判重开 | 8 次 | **0 次** |
| Gecko GPU 崩溃 | 88 次/窗口 | **0** |
| 空闲 10 分钟存活率 | — | **30/30** |

累计 38 局：我方升级 53%（自研模式 11 局 73% / 基线模式 27 局 44%）。

## 六、运维要点（复用）

1. 换承载只需改两个环境变量（`BROWSER_PKG`/`BROWSER_ACT`），脚本无需改动。
2. 夜跑窗口脚本已加两道保底：**8123 服务无响应自动拉起** + **开跑前 `adb connect`**。
3. 大 APK 安装（>90MB）会让 adbd 掉线：`docker restart cloudphone-redroid` → `adb connect 127.0.0.1:5555` → 先 `pm list packages` 确认是否已装上，避免重复安装。
4. **怀疑"环境不稳"前先做空闲对照实验**（不驱动、只采样）：能区分"承载真不稳"与"自愈太积极"。

## 七、遗留

- 麻将（電脳麻将）"点击出手"未打通（手牌经无障碍树可读，点击后手牌不变）。
- 斗地主 belief 漂移（读牌与内部记忆不一致）——另立课题。
- 动作无效回执阈值的进一步校准（当前已用"相对基线 + 回合交出"双判据）。
