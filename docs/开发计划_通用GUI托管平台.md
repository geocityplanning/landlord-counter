# 开发计划：云手机「通用 GUI 托管」平台

> 版本: V1.0 (2026-09-07) | 硬件基线: 4核8G ECS + redroid + 云VLM(glm-4v-plus)
> 定位: **记牌器只是最小 demo；产品 = 云手机 + 通用 GUI 托管能力（面向游戏厂商，做留存）**
> 覆盖路线: 斗地主(wishday) → 掼蛋 → 麻将 → 任意可托管游戏

## 一、架构（锁定，全部游戏无关，per-game 只差一份 profile）

```
[感知] screen      adb 截屏 / ROI / 手牌行亮带定位
  → [识别] vision   VLM 直读(glm-4v-plus) 主链路；RapidOCR 廉价变化闸门；出牌区读取
  → [状态] tracker  54张牌堆约束；手牌/出牌/剩余/对手推理；对局相位机(发牌/叫分/补底/出牌/结算)
  → [校正] reconcile 硬约束(≤4张/王≤1/单调递减) + 数量锚 + 差异优先 + 冲突重问投票  → 88%→95%+
  → [决策] decision 接口化: v1 规则bot(记牌感知) / v2 DouZero 预训练推理(4核CPU可跑)
  → [执行] action   adb 点击(选牌上提/出牌/不出/叫分)，参考 agentos device-adapter
[profile] profiles.py  每游戏一份: ROI/识别方式/提示词/按钮表/期望张数
[评估] watch_game 日志 → 每局 ground-truth 恢复率 / 托管完整度
```

关键约束（吸取 2核4G 阶段教训）：
- rlcard/DouZero 依赖 torch → 4核8G 可上机但**决策进程化**（跑完退出，别常驻）
- 识别只在"事件发生"时调用（指纹闸门），VLM 调用次数 = 局面变化次数而非轮询次数

## 二、里程碑

### M0 平台基线（✅ 基本完成）
4核8G 全栈起（binder 持久化/redroid/mall/osctl/直播）；landlord-counter 入库+CI 绿；
识别基线 88%（17张全读出）; GameProfile 抽象落地。

### M1 对局感知完整化（~1 天）
1. **真局追踪**（3-5h）：相位机（发牌/叫分/补底/结算检测+重置）+ 出牌区读取 + `watch_game` 整局日志
2. **reconcile 一致性纠错**（3-4h）：四把刀 + `tools/test_reconcile.py` 合成噪声测试
- 验收：一局自动跑完日志干净无串局；**合成恢复率 ≥95%**、实局手牌误差 ≤1 张

### M2 托管闭环 v1：规则bot + 点击（1.5-2 天）
1. 规则层补全：顺子/连对/三带一/三带二/飞机/四带二 + beats（~250 行+单测）
2. 决策 v1：记牌感知启发式（能跟/拆/不出），与 tracker/reconcile 同数据
3. 点击执行：按钮标定（出牌/不出/提示/叫分/选牌上提，像素标定法）+ adb action 层
- 验收：**AI 托管完整打完一局，零人工干预**；出牌合法率 100%

### M3 决策 v2：DouZero 换件（1-2 天，升级后可行）
预训练模型 CPU 推理（集成参照 Vincentzyx/DouZero_For_HLDDZ_FullAuto 逐手调用法）
- 验收：同接口替换；与规则 bot 的托管胜率对比数据

### M4 平台化：第二游戏 = 掼蛋（~1 周）
规则层已有（GuanDanRules）；新增：掼蛋视觉适配包（牌面布局标定）+ 状态机差异适配
- 验收：掼蛋可托管一局 → 证明"新增游戏 = 加 profile"的平台命题

### M5 厂商演示包（~2-3 天）
一键拉起环境脚本（升级后多实例）；批量托管跑局数据/胜率报告；osctl 直播门户接入托管过程
- 验收：演示时一句话起环境、直播看 AI 托管、给留存/托管效果数据

## 三、风险与对策
| 风险 | 对策 |
|---|---|
| 自绘按钮 OCR 读不出文字 | 像素标定（商城已趟过）；托管核心按钮有限(~6 个) |
| VLM 单次 2-5s 延迟 | 事件驱动（变化才读）；4核8G 后可上本地 3B VLM |
| 串局污染状态 | 相位机 + 结算检测自动重置 |
| OCR/切片对重叠不稳 | OCR 降级为闸门，识别主链路=VLM（已实测） |
| DouZero torch 内存 | 决策进程化跑完退出 |

## 四、近期执行顺序（建议）
M1 → M2 → M3 → M4 → M5；M1 内 reconcile 与真局追踪可并行/交织（reconcile 纯代码不依赖牌局）。
每里程碑 commit + CI 验证；真局验证时用 portal 直播旁观。
