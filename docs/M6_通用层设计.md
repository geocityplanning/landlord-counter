# M6 通用层设计（云手机 GUI 托管平台）

> 目标：把"看画面 → 决策 → 点屏幕"的托管能力**与具体游戏解耦**，让接入一款新游戏（麻将/新游）从"重写一遍"变成"实现一个适配器"。

## 一、分层

```
┌───────────────────────────────────────────────┐
│  Runtime（通用，与游戏无关）                    │
│  · 主循环/节拍   · 看门狗自愈(卡死重开)         │
│  · 回执校验/重试 · 统计CSV/心跳/日志            │
│  · 进桌准备(启动页识别→点开始)                  │
└───────────────┬───────────────────────────────┘
                │ GameAdapter 接口(见下)
┌───────────────┴───────────────────────────────┐
│  GuandanAdapter / DoudizhuAdapter / Mahjong... │
│  · 本局/回合判定  · 读牌(视觉)  · 决策          │
│  · 出牌执行(点位/手势) · 结算解读               │
└───────────────────────────────────────────────┘
        │                        │
   Device(adb)              Vision(识别器/VLM)
```

## 二、接口（`src/landlord_counter/platform/types.py`）

```python
class GameAdapter(ABC):
    name: str                      # "guandan" / "doudizhu" / ...
    package: str | None            # 示例: None(网页版) / "com.doudizhu.game"

    def start_button(self, frame) -> Point | None      # 开始/续局大按钮(没有=None)
    def sense(self, frame) -> Observation              # 感知: 是否轮到我 / 手牌 / 桌面 / 按钮
    def decide(self, obs) -> Action                    # 决策: play(带组合) / pass / none
    def execute(self, action, obs) -> ExecResult       # 执行: 点选+确认, 内置重试/校验
    def settle(self, frame) -> SettleInfo | None       # 结算解读(用于统计)
```

- `Observation`：`frame/my_turn/hand/table/buttons/extra`
- `Action`：`kind ∈ {play, pass, start, none}` + `combo` + `meta`
- `ExecResult`：`ok/retries/detail`

**约定**：`execute` 必须自带**回执校验**（手牌减少 / 回合交出），失败返回 `ok=False`，由 Runtime 决定重试或回落。

## 三、Runtime 职责（`platform/runtime.py`）

| 职责 | 说明 |
|---|---|
| 进桌 | 每轮先看 `start_button()`，有就点（开始游戏/再接一局） |
| 节拍 | `sense → decide → execute`，间隔可配；非我回合短睡 |
| 看门狗 | N 秒无进展（无按钮/无动作/手牌像素无变化）→ 调 `device.recover()`（重开浏览器/重启 App） |
| 统计 | `settle()` 有结果 → 追加 CSV（时间/局号/结果/模式标签） |
| 心跳 | 每 60s 打一行日志（便于夜间排障） |

## 四、接入新游戏（以麻将为例的清单）

1. 新建 `platform/games/mahjong.py`：实现 `GameAdapter`
2. 标定几何/配色（截图量手牌带、按钮位置、抬起像素）→ 写进适配器或 `docs/` 几何参考
3. 规则/决策：移植开源规则引擎或接自研 AI（接口只需给出 `combo`）
4. 执行：`execute()` 用平台通用"点选 → 校验 → 确认 → 回执"工具（`platform/gestures.py`）
5. 注册到 `platform/registry.py`；`Runtime(adapter=...)` 即可跑，夜跑脚本复用窗口制

## 五、迁移策略（不破现有）

- 现有 `guandan/agent.py`、`tools/auto_play.py` **保持可用**（生产入口不动）
- 新适配器先做"薄封装"：把已有感知/决策函数接进接口（允许过渡期耦合）
- 逐项把通用逻辑（看门狗、回执、统计、进桌）从 agent 移入 Runtime，agent 变薄
- 每步都跑真机验证（≥1 局）与既有测试

### 落地过程中踩到的坑（已修，写进代码注释）

1. **回合判定必须含"按钮可用"**：残局手牌仍显示但按钮禁用 → 误判我方回合 → 空转（`percept.play_button_active`: 亮金 G>120）
2. **抬起度量口径**：掼蛋=像素（~1460/张），斗地主=张数（`lifted_count`），且绝对量噪声大 → 手势层参数化 `lift_eps/lift_one/lift_min`，并支持**帧差度量** `lift_diff`（斗地主用 `lifted_delta`）
3. **按钮块返回 4 元组**（x,y,w,h）→ 统一取前两位
4. **阶段区分**：斗地主"叫分轮"与"出牌轮"必须分开（红钮铁证 + 稳定双帧）

### 说明（斗地主适配器的设计取向）

- **不维护 belief，每回合重读手牌**（比旧链路的 belief 漂移更稳）；读失败时本轮不动作、等下一轮重读
- 结算统计：`settle()`（结算屏 VLM 判"赢/输"）→ Runtime 写 CSV（含 mode tag）；尚未在本窗口跑到完整结算，待夜间/长跑验证
- 跟牌执行一律走"提示选牌"（已验证可靠），领牌走直选（我们的决策）
