# M6 接入清单 · 实操版（新游戏接入 playbook）

> 目的：把"接入一款新游戏"从"重写一遍托管"变成"填一张表 + 写一个适配器"。
> 本文以 **斗地主（App）**、**掼蛋（Web）** 为已完成样例，以 **麻将（電脳麻将，Web）** 为进行中的验收样例。

## 0. 验收标准（Definition of Done）

- [ ] 适配器实现 `platform/types.py::GameAdapter` 五个方法（`start_button/sense/decide/execute/settle`）
- [ ] `platform/test_runtime.py` 离线单测通过（假设备即可，不依赖真机）
- [ ] 真机通过 `Runtime` 连打 ≥1 局（出牌/不出有日志、结算能落 CSV）
- [ ] 几何/配色标定写进 `docs/` 或代码注释（换分辨率/皮肤时能快速重标）
- [ ] 失败可恢复：卡死有看门狗、执行有回执与重试、决策失败有兜底

## 1. 选型（半天内）

| 类型 | 要求 | 样例 |
|---|---|---|
| App | 单机/离线可玩、无强制登录、小包体 | 斗地主 wishday（`com.doudizhu.game`） |
| Web | 可本地托管（静态资源或可构建）、画布/HTML 交互 | 掼蛋 `yangfanconan/guandan`（www 直托管）、麻将 `kobalab/Majiang`（MIT，`npm run build` 出 dist） |

**网络注意（ECS 实测）**：`github.com` 直连超时 → 用 `api.github.com` 的 tarball 接口下载；`registry.npmjs.org` 慢 → `npm install --registry https://registry.npmmirror.com`。

## 2. 装机 / 托管（半天内）

- **App**：`adb install -r xxx.apk`；大包安装可能把 adbd 搞挂 → `docker restart cloudphone-redroid` 后确认已装
- **Web**：静态资源放 `reference/<game>/`，写幂等脚本 `tools/serve_<game>.sh`（如 8123 端口服务 `reference/guandan/www`；麻将 8124 服务构建产物 `dist/`），手机端用 **Firefox Focus** 打开 `http://172.18.0.1:<port>/`
- **判定"页面可用"**：截图后能看到首屏关键按钮/元素；若空白/半渲染 → `am force-stop` 重开（脚本化）

## 3. 几何标定（1-2 小时）

```bash
python3 tools/onboard_geometry.py          # 现场截屏 → 行剖面/主色/按钮色块报告
python3 tools/onboard_geometry.py shot.png # 或分析已有截图
```

产出需要记录的常量：

| 项 | 说明 | 样例（掼蛋） |
|---|---|---|
| 手牌带 | y 区间 + 白卡像素阈值 | y[805,945]，阈值 4000 |
| 牌位公式 | 起点/间距（整排居中） | `startX=(720-((n-1)*24+88))/2` |
| 按钮 | 提示/出牌/不出 坐标 + 可用态配色 | (199,1119)/(359,1119)/(519,1119)；亮金=可用 |
| 回合判据 | 怎样算"轮到我" | 手牌白卡≥4000 **且 出牌按钮可用** |
| 抬起度量 | 选牌验证用（像素或帧差） | 像素≈1460/张；斗地主用帧差 `lifted_delta` |

**踩过的坑（务必按表检查）**
1. 只看手牌白卡会误判回合（残局手牌仍显示但按钮禁用）→ 必须加"按钮可用"
2. 抬起度量口径不同（像素 vs 张数）且绝对量噪声大 → 优先**帧差**
3. 色块函数可能返回 4 元组（x,y,w,h）→ 点击取前两位
4. 阶段区分（斗地主叫分轮 vs 出牌轮）→ 用"铁证"（如红钮）+ 稳定双帧

## 4. 写适配器（半天）

```python
class XxxAdapter(GameAdapter):
    name, package/start_url = ...
    def start_button(self, frame) -> Point | None: ...      # 开始/续局大钮
    def sense(self, frame) -> Observation: ...              # 是否我回合/手牌/待压牌/按钮
    def decide(self, obs) -> Action: ...                    # play(组合)/pass/bid/none
    def execute(self, action, obs) -> ExecResult: ...       # 走 platform/gestures.Executor
    def settle(self, frame) -> SettleInfo | None: ...       # 结算判读(用于统计)
```

- 执行**一律复用** `platform/gestures.py` 的 `Executor`（点选逐张验证+扫点 / 提示选牌+回执 / 两轮重试）
- 决策可插：规则引擎 / 开源 AI / 强化学习模型（如 DouZero），失败要能回落
- 注册到 `platform/registry.py`，入口 `tools/run_via_platform.py <秒> <name>`

## 5. 验证（1 小时）

```bash
PYTHONPATH=src python3 -m landlord_counter.platform.test_runtime      # 离线
PYTHONPATH=src python3 tools/run_via_platform.py 300 <name>           # 真机
```

### 麻将实测记录（2026-09-11）

- **a11y 直接给出**：手牌 = 14 个 Button 节点（文字为牌名，如 `チーワン`/`シャー`，y≈738-788，间距 36）；牌桌信息（`東一局`/`点数`/`ドラ`）；决策提示文本（`シモチャからポン`）；按钮（`音声OFF [a]`/`速度- [-]`/`速度+ [+]`）。
- **出手机制（源码）**：`majiang-ui` 的 `setSelector(..., {confirm:'Enter'})` → **Enter 确认聚焦项**；出手阶段聚焦"最后一张手牌"。已实现 ENTER 主路径 + 点击兜底。
- **卡点**：遇到 `ポン/チー` 决策提示时游戏等待回答（提示框为黑底白字，实测点击无响应）；且**页面点击常整体失灵**（与 guandan 的"Focus 不吃点击"同源，怀疑与频繁 a11y dump 有关，待验证：dump 前/后点击响应对比）。
- **决定性实验（点击 vs 按键）**：同一页面实例里 tap 提示框帧差 **0.00**（连 dump 前后都一样）→ 不是 dump 影响；而发一次 `keyevent BACK` 帧差 **132** ⇒ **触控失灵但键盘通道有效**。
- **因此的路线调整**：麻将（以及将来遇到"点击失灵"的游戏）可走**键盘驱动**：`majiang-ui` 的 `setSelector` 支持 `prev: ArrowLeft / next: ArrowRight / confirm: Enter`，按钮组同样走 selector ⇒ 方向键选、Enter 确认；`adb shell input keyevent <码>` 即可。
- **下一步**：① 键盘驱动整局验证（重启页面 → 方向键+Enter 完成摸打）② 决策提示（ポン/チー）用按键应答 ③ 回合判定结合"提示文本/手牌张数/计时器"多信号

> 说明：麻将（四人完整规则 + AI）是 M6 的"通用性验收"，本表按第 1-6 步推进；每步产物都留档，便于复用。
