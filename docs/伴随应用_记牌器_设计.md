# 记牌器伴随应用 · 设计（2026-09-18 定稿，等对账跑完开工）

## 0. 一句话

**只做"看和记"**：牌局开始 → 谁出了什么 → 各点数剩几张 → 本局可出方案 1/2/3，
全部落 SQLite。**不碰"手"**（点牌仍由托管那条线管），两条线将来靠 IPC 合成一个安装包。

## 1. 数据源：一个接口，三个实现（解耦的关键）

```
BoardSource (接口)
  ├─ TruthSource   ← 近期用(插桩版游戏 __truth())      已验证: 出牌动作 14/14 逐张一致
  ├─ VisionSource  ← 产品/闭源游戏(纯视觉)              待磨: 读牌 16/23、桌面识别
  └─ IpcSource     ← 自家棋牌包(进程内直读状态)         未做: 等自家包
```

**记牌器只依赖接口** ⇒ 换源不改业务 ✓。
每个源只提供一种事件：`ObsEvent(ts, seat, cards, my_hand, phase, turn)`，
其中 `cards` = **带花色**的牌（[zhi, hua]；花色编码 0♠1♥2♣3♦4王，与游戏源码一致 ✓）。

## 3. SQLite（表结构）

```sql
-- 每局一行
CREATE TABLE deal (
  deal_id TEXT PRIMARY KEY,      -- gd-20260918-1426 形式
  started_at INTEGER, ended_at INTEGER,
  ji_pai INTEGER,                -- 当前级牌(打几)
  seat_me TEXT DEFAULT '南',
  result_raw TEXT, win INTEGER, upgrade INTEGER
);
-- 每一手一行（"谁出了什么"）
CREATE TABLE play (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  deal_id TEXT, ts INTEGER,
  seat TEXT, cards TEXT,         -- "♣J ♥J"，带花色
  n INTEGER, is_mine INTEGER,    -- 是否我方出的
  hand_left INTEGER
);
-- 我方的每一次决策 + 对账结果（"每一手的准确性"）
CREATE TABLE decision (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  deal_id TEXT, ts INTEGER,
  hand_before INTEGER,
  planned TEXT,                  -- 决策要打的牌
  actual TEXT,                   -- 游戏真值里实际打出的
  identity_ok INTEGER,           -- 1=逐张一致(含花色)
  source TEXT                    -- truth / vision / ipc
);
-- 每局的剩余张数快照（供回放/复核）
CREATE TABLE remains_snapshot (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  deal_id TEXT, ts INTEGER, rank INTEGER, left_count INTEGER
);
```

**规矩**（沿用现有纪律 ✓）：库只落**本地** ✓；牌局数据**绝不入公开仓** ✓（`.gitignore`）。
