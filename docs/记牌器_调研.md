# 记牌器调研（2026-09-16）

> 目标（用户）：斗地主 + 掼蛋都要记牌器，且**后台能查**（谁打了什么牌 / 池子还剩什么）。
> 调研问题：有没有现成开源可抄？我们要抄什么？

## 一句话结论

**"记牌器"本身没有开源可抄** ✗（现成的要么闭源，要么是外挂性质、不可用）；
但**三样东西可以直接抄** ✓ —— 而且抄完我们的数据模型就能**直接喂 RL**，不返工：

| # | 抄什么 | 从哪抄 | 落到我们哪 |
|---|---|---|---|
| ① | **状态/记牌的输出清单**（记牌器到底要产出哪些字段）| DouZero 的 `infoset` | `GameLog` / `CardTracker` 的输出字段 |
| ② | **状态编码规范**（多少维、怎么归一化）| MonadMorph（掼蛋）/ DouZero（斗地主）| 喂 RL 的状态构造 |
| ③ | **评估口径**（怎么判强弱）| 同上的论文/仓库 + 我们的队伍指标 | 夜跑统计口径 |

## ① 斗地主：DouZero 的 `infoset` = 记牌器的**输出清单**

来源：`douzero/env/env.py`（本机 venv 内）+ 我们的适配 `src/landlord_counter/logic/douzero_bridge.py`

| DouZero 字段 | 含义 | 记牌器能否给 | 我们现在 |
|---|---|---|---|
| `player_hand_cards` | 我的手牌 | ✓ 读牌 | ✓ 有 |
| `num_cards_left_dict` | 三家余牌**张数** | ✓ 记牌器 | 🟡 粗估 |
| `other_hand_cards` | 对手**并集牌池**（54 − 我手 − 已出）| ✓ 记牌器 | 🟡 现算 |
| `card_play_action_seq` | **出牌序列**（谁打了什么，按序）| ✓ 记牌器 | 🟡 只取最近 15 手 |
| `last_move` / `last_two_moves` / `last_move_dict` | 最近出牌 | ✓ 记牌器 | 🟡 部分 |
| `played_cards` | **各家已出的牌**（按角色）| ✓ 记牌器 | ✗ **置空**（缺口）|
| `bomb_num` | 已出炸弹数 | ✓ 记牌器可数 | ✗ 置 0（缺口）|

→ **这张表就是我们记牌器的验收清单** ✓：全部字段都要能从记牌器取到。

## ② 掼蛋：MonadMorph 的 20-token 状态规范（我们已反推）

来源：`reference/guandan-rl/`（本项目已入库，`UPSTREAM.md` 有完整说明）

| token | 维度 | 含义 | 记牌器能否给 |
|---|---|---|---|
| 0 | 16 | 手牌（15 点数 + 同花可成组数，/8）| ✓ 读牌 |
| 1..16 | 16×16 | **最近 16 手出牌**（玩家 one-hot + 牌型 one-hot + rank/14）| ✓ 记牌器（**这就是"谁打了什么牌"** ✓）|
| 17 | 5 | **各方余牌**（我/下家/对家/上家/合计，/108）| ✓ 记牌器（**必须按张数给准**）|
| 18 | 16 | 上家最近一手 | ✓ 记牌器 |
| 19 | 4 | 我方座位 one-hot | ✓ |

→ 我们现在的 `_rl_played` 是"按座位累加张数"✗（不按点数、也会漏采 ✗）→ **换成 `CardTracker` 即可** ✓。

## 评估口径（抄 + 我们的）

| 口径 | 来源 | 我们的 |
|---|---|---|
| 胜率 | DouZero 论文 | ✓ 但**必须按队伍口径**（掼蛋是 2v2）|
| 场均升级数（有符号）| 掼蛋规则（双上 +3 / 单下 +2 / 其它 +1）| ✓ 已实现 |
| 头游率 / 双上率 / 被双下率 | 掼蛋特有 | ✓ 已实现 |
| 队友名次分布 | 组队打法（辅助队友）| ✓ 已实现 |
| 操作准确率（打出的牌 == 想的牌）| —— | ✓ 我们自己的硬指标（≥99%）|
